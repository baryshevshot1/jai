# Jarvis AI (`jai`)

Боксовый офлайн ИИ-ассистент для бизнеса. Десктоп-приложение, которое после установки
работает **полностью на компьютере пользователя**: без облака, данные не покидают ПК
(152-ФЗ), без терминала.

- **Скачать:** [последний релиз](https://github.com/baryshevshot1/jai/releases/latest)
- **Что нового:** [`CHANGELOG.md`](./CHANGELOG.md)

## Установка

### Что нужно

| | Минимум | Комфортно |
|---|---|---|
| Система | Windows 10/11 x64 · Ubuntu 22.04+ · macOS (Apple Silicon) | — |
| Память | 8 ГБ ОЗУ | 16 ГБ ОЗУ или видеокарта NVIDIA от 6 ГБ |
| Диск | ~15 ГБ свободно | 20+ ГБ (модели весят 1–7 ГБ) |
| Интернет | только чтобы скачать модели один раз | не нужен вовсе, если ставить с флешки |

Нужен движок **Ollama** — приложение само его находит, запускает и гасит, но **не
устанавливает**: это разовый шаг при развёртывании.

### Шаг 1. Движок Ollama

| Система | Как |
|---|---|
| Windows | <https://ollama.com/download/windows> → `OllamaSetup.exe` → «далее-далее» |
| Linux | `curl -fsSL https://ollama.com/install.sh \| sh` (создаёт systemd-сервис) |
| macOS | <https://ollama.com/download/mac> или `brew install ollama` |

### Шаг 2. Приложение

Файлы — на странице [последнего релиза](https://github.com/baryshevshot1/jai/releases/latest).

**Windows 10/11** — `Jarvis.AI_<версия>_x64-setup.exe` (~200 МБ; внутри офлайн-установщик
WebView2, докачивать ничего не нужно).
При запуске появится синее окно «Система Windows защитила ваш компьютер» — это
ожидаемо, сборка пока без платной подписи кода: **«Подробнее» → «Выполнить в любом
случае»**.

**Linux** — любой из трёх:

```bash
sudo apt install ./Jarvis.AI_<версия>_amd64.deb     # Ubuntu / Debian (зависимости подтянутся)
sudo dnf install ./Jarvis.AI-<версия>-1.x86_64.rpm  # Fedora / RHEL
chmod +x Jarvis.AI_<версия>_amd64.AppImage && ./Jarvis.AI_<версия>_amd64.AppImage  # любой дистрибутив
```

Если AppImage не стартует — поставить `libfuse2`.

**macOS (Apple Silicon)** — `Jarvis.AI_<версия>_aarch64.dmg`, перетащить в «Программы».
Первый запуск: **правый клик по приложению → «Открыть» → «Открыть»** (нотаризация — в Стадии 2).

### Шаг 3. Модели

Запустите **Jarvis AI**. При первом запуске откроется **мастер установки**: он оценит
компьютер, покажет, какие модели тот потянет, и поставит их — из интернета или с флешки.
Терминал не нужен.

Позже мастер доступен из **Настройки → Модели → «Мастер установки…»**, а отдельные
модели ставятся кнопкой «Установить» в том же разделе.

Базовый набор: `qwen3.5:9b` (чат, ~6,6 ГБ) + `bge-m3` (поиск по документам, ~1,2 ГБ).
На слабой машине вместо `9b` — `qwen3.5:4b`. По желанию: `qwen3-vl:4b` (картинки и OCR),
`qwen3-coder` (код).

**Выбирать модель в работе не нужно** — приложение подбирает её само (см. ниже).

## Установка без интернета — с флешки

Готовая флешка ставит всё на чистой машине: движок, приложение и модели.

**На флешке:**

```
ПРОЧТИ-МЕНЯ.html      — инструкция для того, кто устанавливает
Windows/  Установить.bat + setup.exe + OllamaSetup.exe
Linux/    install.sh + .deb + .AppImage + ollama-linux-amd64.tgz
macOS/    Jarvis.AI_….dmg
models/   каталог моделей Ollama — приложение найдёт его само
```

**У клиента:** запустить `Windows\Установить.bat` (или `bash Linux/install.sh`) → открыть
Jarvis AI → мастер установки **сам найдёт папку `models` на флешке** и предложит импорт.
После импорта флешку можно извлечь — всё работает с диска.

**Собрать флешку** (на машине разработчика; части независимы):

```bash
# установщики приложения (последний релиз) + Ollama + скрипты
tools/make-usb.sh --out /Volumes/JAI --installers

# модели: ollama pull → выборочное копирование blobs/manifests (нужны ollama и jq)
tools/make-usb.sh --out /Volumes/JAI --models "qwen3.5:9b qwen3.5:4b bge-m3"

# всё сразу, конкретная версия
tools/make-usb.sh --out /Volumes/JAI --installers --models "qwen3.5:9b bge-m3" --version app-v0.3.0
```

> Флешку форматировать в **exFAT**: блоб модели 9B — это один файл ~6 ГБ, а FAT32 не
> хранит файлы больше 4 ГБ. Объём — от 16 ГБ.

## Возможности

**Модель подбирается сама.** Обычный вопрос — текстовая модель, вопрос с картинкой —
модель зрения. Мощная машина получает модель посильнее, слабая — полегче. Не хватает
памяти прямо сейчас — приложение снизит контекст или возьмёт модель поскромнее, а не
упадёт. Ручной выбор есть в настройках, но он не нужен.

**Чат.** Ответ печатается на глазах и сразу форматируется (таблицы, формулы, код с
подсветкой). Видно, сколько идёт ожидание. Под ответом — «Копировать» и «Повторить».
Режим «Размышления» — для моделей, которые это умеют. `Esc` — стоп, `Ctrl/Cmd+N` — новый чат.

**Документы (RAG).** PDF, Word (`.docx`), текст, Markdown — прикрепить к сообщению или
положить в базу знаний. Поиск по смыслу (`bge-m3` + sqlite-vec), под ответом видно
источники. Всё офлайн.

**Проекты.** У каждого — своя база документов и свои инструкции («ты юрист компании X,
отвечай со ссылками на приложенные договоры»). Чаты проекта ищут только по его базе.

**Зрение и OCR.** Картинки распознаются, текст с них извлекается (`qwen3-vl`).

**Операционный слой.** Мастер установки, установка моделей из окна с прогрессом и честной
отменой, импорт с флешки, проверка обновлений моделей, автообновление приложения,
«Проверка системы» (движок, модели, база, диск, железо, хранилище).

**Защита слабых машин.** «Светофор» железа, щадящий режим (половина ядер CPU — машина не
перегревается; на слабом железе включается сам), температурный сторож, безопасное
сохранение истории при внезапном выключении.

**Интернет — только по команде.** По умолчанию приложение полностью офлайн. Онлайн-режим
включается тумблером и даёт модели два инструмента: веб-поиск и чтение страницы по ссылке.
Видно, что нашлось (ссылки под ответом) и что ушло наружу (журнал в настройках).

Полный список изменений по фичам — в [`CHANGELOG.md`](./CHANGELOG.md).

## Разработка

Разработка и запуск — **только на macOS**. Установщики Linux/Windows собираются в CI
(Tauri не умеет кросс-компиляцию).

### Что поставить один раз

- **Node.js** — версия в [`.nvmrc`](./.nvmrc); с [nvm](https://github.com/nvm-sh/nvm):
  `nvm use` в папке проекта.
- **Rust:** `curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh`
- **Ollama** — нужна только чтобы получать ответы. Окно откроется и без неё (в шапке будет
  «Движок не отвечает»).
  ```bash
  ollama serve              # если не запущен как сервис
  ollama pull qwen3.5:9b    # на слабом железе — qwen3.5:4b
  ollama pull bge-m3        # поиск по документам
  ```

### Запуск

```bash
npm install          # только в первый раз
npm run tauri dev    # поднимает Vite (порт 1420) и открывает окно
```

Первая сборка Rust — несколько минут, дальше секунды.

### Проверки перед коммитом

```bash
npm run build                              # tsc (strict) + vite build
cargo test --manifest-path src-tauri/Cargo.toml
```

CI гоняет то же самое на Ubuntu и Windows при каждом PR.

### Освободить память после работы

Закрытие окна **не** выгружает модель — Ollama держит её в памяти ещё ~5 минут:

```bash
ollama stop qwen3.5:9b   # или все сразу:
ollama ps | awk 'NR>1{print $1}' | while read m; do ollama stop "$m"; done
ollama ps                # проверить, что памяти ничего не занимает
```

### Выпуск релиза

1. Поднять версию в **пяти** файлах: `package.json`, `package-lock.json`
   (`npm install --package-lock-only`), `src-tauri/Cargo.toml`, `src-tauri/tauri.conf.json`
   и `docs/Инструкция_тестирования.md` (там ссылки на скачивание прибиты к тегу).
2. В `CHANGELOG.md` закрыть раздел «Не выпущено» как `[X.Y.Z]`.
3. Тег → сборка:
   ```bash
   git tag app-vX.Y.Z && git push --tags
   ```
4. CI соберёт установщики трёх ОС и создаст **черновик** релиза.
   **Черновик нужно опубликовать вручную** — иначе автообновление на новую версию
   не сработает.

## Структура

```
index.html              — точка входа фронтенда (Vite)
src/                    — фронтенд (TypeScript, 17 модулей)
  main.ts               — точка сборки: инициализация и порядок старта
  chat.ts               — ядро чата: контекст, RAG, стриминг, авто-модель по задаче
  models.ts             — подбор модели, каталог моделей, «светофор» железа, движок
  documents.ts          — база документов и индексация
  projects.ts           — проекты (своя база и инструкции)
  attachments.ts        — прикрепление документов и картинок
  settings.ts           — страница настроек, диагностика, обновления, тема
  online.ts             — онлайн-режим и журнал обращений в интернет
  wizard.ts             — мастер установки при первом запуске
  conversations.ts      — история диалогов
  pull.ts               — установка моделей (единый прогресс/отмена)
  ui.ts · dom.ts · state.ts · util.ts · types.ts · markdown.ts
  styles.css
src-tauri/src/          — бэкенд Rust
  lib.rs                — Tauri-команды: чат, модели, документы, настройки, диагностика
  engine.rs             — управление процессом Ollama (запуск/останов/пути)
  docstore.rs           — векторное хранилище (SQLite + sqlite-vec)
  embed.rs · chunk.rs   — эмбеддинги bge-m3, разбивка текста
  provision.rs          — импорт моделей с носителя, оценка посильности
  tools.rs              — онлайн-слой: веб-поиск и чтение страниц
tools/make-usb.sh       — сборка флешки «под ключ»
usb/                    — что кладётся на флешку (скрипты установки + ПРОЧТИ-МЕНЯ)
.github/workflows/      — CI (проверки на PR) и сборка установщиков по тегу
docs/                   — документация и проектные материалы
```
