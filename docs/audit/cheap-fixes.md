# Дешёвые правки: пул для быстрой части волны 0

Дата: 2026-08-04. Ответ на вопрос заказчика о метке `trivial_fix`.

## Главное: метка `trivial_fix` оказалась слишком узкой

`trivial_fix: true` стоит всего у **4 находок, и все они P3** — F-FRONTEND-001 (удалить сиротский каталог), F-QUALITY-002 (обновить postcss), F-FRONTEND-005 (humanError в одном месте), F-FRONTEND-008 (добавить поле в TS-тип). Я ставил метку в узком смысле «правка на одну строку, не требующая думать» — и по этому критерию она честна, но для планирования волны бесполезна: из четырёх косметических правок волна не собирается.

**Практически полезный срез — `cost: S` (меньше дня работы): таких находок 38 из 52**, из них 36 с низким риском правки:

| Severity | Сколько | Из них помечено trivial_fix |
|---|---|---|
| **P0** | **4** | 0 |
| **P1** | **4** | 0 |
| P2 | 18 | 2 |
| P3 | 12 | 2 |

То есть **восемь находок уровня P0/P1 чинятся меньше чем за день каждая** — это и есть настоящая быстрая часть волны 0. Ниже полный список, отсортированный по severity; ★ — помечено `trivial_fix`.

## Что из этого складывается в связки

Дешёвые правки выгоднее делать не по одной, а группами — у нескольких находок общий корень, и правка одного места закрывает сразу несколько:

1. **Связка «отказ ≠ пустота» (P0+P1, ~2–3 дня на всё).** F-BACKEND-001 (очистка истории), F-BACKEND-006 (каскад удаления), F-BACKEND-008 (settings.json), F-SECURITY-001 (журнал 152-ФЗ), F-BACKEND-009 (список диалогов), F-FRONTEND-002/010 (фронтовая половина). Все чинятся одним приёмом: различить `NotFound` и прочие отказы, вернуть `Err`, показать состояние «не удалось прочитать». Закрывает 4 из 9 P0.
2. **Связка «наблюдаемость» (P1/P2, ~1 день).** F-BACKEND-004 (цепочка причин в `from_reqwest`), F-BACKEND-011 (ошибки аудиопотока мимо журнала), F-BACKEND-014/018 (engine.rs не пишет в журнал вовсе), F-FRONTEND-009 (11 точек `set_setting` в `console.error`). Один помощник записи + правка мест вызова.
3. **Связка «async-атрибуты» (P1, полдня).** F-BACKEND-016: пометить `#[tauri::command(async)]` команды истории, проектов, настроек и поиска носителей — правка атрибута, поведение не меняется. Снимает замирание окна после каждого ответа.
4. **Связка «стриминг» (P2, ~1 день).** F-FRONTEND-014: во время потока показывать обычный текст, полный Markdown рендерить один раз на финале. Именно тот пример, который назвал заказчик: правка небольшая, а на целевой машине убирает 388 полных перерисовок из 388.

## Чего в этом пуле нет

Дорогие находки (`cost: M/L`), которые в быструю волну не помещаются и требуют отдельного решения: F-PROVISIONING-002/003 (канал выпуска и Windows-сборка — организационное решение владельца), F-SECURITY-002 (изоляция разбора PDF в отдельный процесс), F-QUALITY-003 (тесты основного сценария), F-FRONTEND-012 (виртуализация ленты), F-BACKEND-017 (маркер владения процессом движка), F-PROVISIONING-001 (обновление sysinfo с перепроверкой).
