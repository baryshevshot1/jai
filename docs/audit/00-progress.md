## Ключевые решения и контекст (для следующих сессий)

- Ветка доставки: `claude/jai-audit-phase-0-v0ikt3` (навязана средой, вместо audit/phase-0 из задания). Коммитим только `docs/audit/**`.
- Расхождения задания с фактом (репозиторий прав): llama.cpp-сайдкара нет (Ollama — единственный движок); C1-3 устарел — ветка voice влита (PR #36–39), PR #35 влит 2026-08-03, stash в облачном клоне пуст принципиально; ESLint-конфига нет.
- ID находок присваивает только главный агент, сквозная нумерация по областям в findings.jsonl.
- Среда: GUI-сборка невозможна (нет дисплея); cargo/npm-реестры доступны через прокси; системные webkit2gtk-зависимости ставились apt'ом в сессии 1 (в свежей сессии их может не быть — ставить заново при необходимости).
- Контроль «ничего вне docs/audit» вести против **origin/main** (локальный `main` в клоне может отставать — обновлять `git branch -f main origin/main`).
- **Ритм сдачи (с этапа A2a):** по завершении этапа коммит+пуш в ветку, заказчик мержит PR, следующая сессия начинается с `git fetch origin main` и перевода ветки на актуальный main. **Осторожно:** PR может быть создан ДО последнего пуша — перед `reset --hard origin/main` проверять `git log origin/<ветка>` и, если этапный коммит в main не попал, восстанавливать файлы `git checkout <sha> -- docs/audit/` (так и случилось с A2a при мерже PR #40).

## Проверка премис C1-1 / C1-2 по текущему main (2026-08-04, до A1)

- **C1-2 («error decoding response body») — премиса устарела: баг исправлен и закреплён тестами.** Клиент больших загрузок (tools.rs:102-129) не имеет общего таймаута — только connect_timeout + read_timeout; voice.rs:278 использует именно его; регрессионный тест `no_total_timeout_on_the_download_path` берёт настоящую заготовку клиента (download.rs:649,687) и прошёл в прогоне E2; journal.rs:226-271 разворачивает цепочку source() у reqwest (тест закрепляет, что «error decoding response body» виден в причинах). Единственный `.timeout()` остался у клиента онлайн-слоя (tools.rs:159) — там он уместен. Для C1 остаётся: оценить полноту схемы логирования (байтовое смещение, Content-Length vs получено) против требований задания.
- **C1-1 (карточка голоса отсутствует в релизе) — премиса с высокой вероятностью устарела: механизм закрыт в волне PR #36–39.** Карточка строится кодом (settings.ts:831-856) с якорем на карточку «Документы»; в startup.test.ts:112-140 три регрессионных теста: карточка появляется (на реальной разметке index.html?raw), строится даже при отказе бэкенда на все команды, init голоса не роняет старт — все прошли (E2). Команды голоса регистрируются всегда (cfg-gated команд нет); release.sh:88 собирает с default features (voice включён); release.yml использует tauri-action без отключения фич. Остаточное: подтвердить на настоящем бандле (E3 → план верификации); замечена молчаливая ветка `if (!after) return;` (settings.ts:832-833) — обсудить в C1.

## Ключевые факты A2b (для следующих сессий)

- **Синхронные tauri-команды выполняются в потоке интерфейса** (проверено по исходникам tauri-macros 2.6.3, не по документации). В проекте 24 таких команды, включая сохранение и перечисление диалогов на каждое сообщение и обход всех томов в мастере. Приём `#[tauri::command(async)]` в проекте известен (documents.rs:36-38) и применён только к пяти командам документов.
- **Владение движком держится на одном флаге в памяти**: Drop нет, сигналов нет, pid-файла нет; единственный хук — RunEvent::Exit. Отсюда сирота после падения и ложная строка диагностики «остановите системную службу Ollama».
- **Правило «отказ ≠ пустота/успех» механически проверяемо только узко**: тип операции + граница cfg(test) дают 17 срабатываний, из них 3 дефекта; соседний journal:: и имя переменной как признаки не работают (посчитано).
- **Windows-стенд обязателен до первой продажи**: 5 из 8 экспериментов блокируют выпуск, и он же нужен как условие производства артефакта.
