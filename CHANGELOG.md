# Журнал изменений — Jarvis AI (`jai`)

Все значимые изменения проекта. Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/);
проект придерживается принципов офлайн-ядра из [`CLAUDE.md`](./CLAUDE.md) (единственный
движок — Ollama на `127.0.0.1`; сеть — только из Rust; данные — в `appDataDir`;
кроссплатформенность Linux/Windows/macOS; сборка установщиков — в CI).

## [Не выпущено] — 2026-07-11

### Changed — Проще боковая панель (по запросу заказчика)
Слева остаются только чаты и проекты; служебное — в настройках.
- Убраны вкладки «Диалоги»/«Документы»: общая база документов (для быстрых
  чатов вне проектов) переехала в настройки — карточка «Документы (быстрые
  чаты)» с теми же возможностями (добавление, список, установка bge-m3,
  импорт с флешки/диска). Базы проектов как были — на экранах проектов.
- Убраны нижние кнопки «Проверка» и «Очистить»: перепроверку железа теперь
  делает кнопка «обновить» в шапке (движок + железо + модели), а удаление всей
  истории — в настройках, карточка «История диалогов» (с подтверждением).

### Added — Живой чат: форматирование на лету, секундомер, «Копировать»/«Повторить»
Итерация 7: ответ выглядит живым от первого токена до последнего, а ожидание —
честным.
- **Markdown при стриминге**: живая печать теперь рендерит форматирование
  (заголовки, списки, код, формулы) по мере поступления ответа, а не одним
  «прыжком» в конце. Перерисовка — не чаще раза в 180 мс, чтобы слабое железо
  не захлёбывалось; финальный рендер по завершении остаётся авторитетным.
- **Секундомер ожидания**: «Думаю над ответом · N с» после четырёх секунд —
  загрузка модели и длинные размышления больше не выглядят зависанием. Статусы
  агентного режима («Ищу в интернете…») тоже идут со счётчиком.
- **Действия под ответом**: «Копировать» кладёт весь ответ в буфер
  (Markdown-исходник), «Повторить» перегенерирует последний ответ на тот же
  вопрос — можно сменить модель или тумблеры и попробовать снова. Кнопки есть
  и у ответов из открытой истории; повтор — только у последнего ответа.

### Added — Флешка «под ключ», фундамент: импорт моделей с носителя + оценка посильности
Первая часть умного инсталлятора (итерация 6а): модели приезжают на флешке и
ИМПОРТИРУЮТСЯ на компьютер, а приложение заранее знает, какие модели набора
машина потянет.
- **Импорт моделей с флешки/диска** (`import_models_from_dir`): копирование
  blobs/manifests в каталог Ollama на компьютере — после импорта носитель можно
  вынуть, чтение моделей не упирается в скорость USB (прежнее «переключение
  каталога» без копирования осталось продвинутым вариантом в «Движок и модели»).
  Дедуп бесплатный (имена блобов = sha256): повтор после отмены продолжает с
  места; частичные копии живут как `.part` и не выглядят готовыми блобами.
  Прогресс, отмена и взаимоисключение со скачиванием — через общий менеджер
  установки (PullState); копирование — в отдельном потоке, чат не блокируется.
  Кнопки «Импорт с флешки/диска» — в карточке документов и разделе «Модели».
- **Поиск носителей** (`find_model_sources`): обход смонтированных дисков
  (съёмные — первыми), валидация manifests+blobs, счёт моделей и объёма —
  найденная флешка предлагается к импорту в один клик.
- **Оценка посильности ДО установки** (`assess_models`): у моделей набора —
  приблизительный вес (`approx_gb` в MODEL_SET) и честный вердикт ok/tight/no
  против текущего железа (общая с plan_inference формула `fit_verdict`, KV по
  q8/f16 в зависимости от движка). Это основа мастера первого запуска
  (следующая итерация).
- Тесты: +5 (дедуп/слияние/идемпотентность импорта, отмена без мусора,
  отклонение не-каталога, статистика источника, fit_verdict) — всего 19.

### Added — Мастер установки при первом запуске
Итерация 6б: приложение само проводит клиента от чистой машины до рабочего
набора моделей.
- Открывается автоматически, когда обязательные модели не установлены (и всегда
  доступен из «Настройки → Модели → Мастер установки…»).
- «Ваш компьютер»: светофор, GPU (со свободной VRAM), ОЗУ, CPU, версия движка.
- «Модели»: весь набор с честными вердиктами против этой машины
  (потянет/впритык/«не потянет» — заблокировано, безопасность прежде всего);
  рекомендуемые отмечены (лучшая посильная текстовая + bge-m3), виден итоговый
  объём на диске.
- «Откуда установить»: найденная флешка (первой) или интернет. С носителя —
  импорт одним действием со сверкой «что из выбранного появилось»; из
  интернета — модели по очереди с прогрессом и честной отменой.

### Added — Инфраструктура флешки: сборка одной командой
Итерация 6в: `tools/make-usb.sh` собирает флешку «под ключ» — установщики
приложения (из релиза GitHub) + движка Ollama + установочные скрипты, и/или
каталог моделей (ollama pull → ВЫБОРОЧНОЕ копирование blobs/manifests по
манифесту). Части независимы: инсталляторы и модели заказываются по отдельности.
На флешке: `Windows/Установить.bat` (тихие установки Ollama /VERYSILENT и
приложения /S, без прав администратора), `Linux/install.sh` (движок в
/usr/local, .deb через apt либо AppImage на диск — exFAT не хранит бит
исполнения), `ПРОЧТИ-МЕНЯ.html` для установщика. README: раздел «Флешка
"под ключ"»; напоминание про exFAT (блобы >4 ГБ).

## [0.2.0] — 2026-07-11

Крупный блок: работа с документами (прикрепление и полноценный RAG), операционный
слой (установка моделей), долговечные настройки, доработки UX и опциональный
онлайн-слой (агентный веб-поиск). Поверх — итерации 3–5 по итогам аудита:
надёжность запросов и честная оценка памяти, единый менеджер установки моделей,
модульная архитектура фронтенда с лёгким стартом.

### Changed — Надёжность: таймауты запросов к движку и честная оценка памяти
Итерация 3 аудита. Зависший движок больше не подвешивает интерфейс, а оценка
памяти перестала быть оптимистичнее реальности.
- **Общий HTTP-клиент** к Ollama (`connect_timeout` 2 с, пул на процесс) вместо
  нового клиента на каждый вызов; метаданные-запросы (`/api/tags`, `/api/ps`,
  `/api/show`, `/api/version`, статус эмбеддера) — таймаут 10 с, `/api/embed` —
  120 с; стримы (чат, установка) без общего таймаута — их защищает отмена.
  Проверка обновлений моделей ходит в реестр ТОЛЬКО изолированным веб-клиентом
  (`tools::web_client`: https_only, UA, 8/20 с) — правило разделения сетевых
  путей восстановлено.
- **Честная память**: KV-кэш считается по f16 для внешнего движка (q8_0
  действует только на процесс, поднятый нами) — оценка не занижается почти
  вдвое; детект видеопамяти отдаёт и СВОБОДНУЮ (`nvidia-smi memory.free`;
  Windows — `IDXGIAdapter3` budget), а не только паспортный объём; в плане
  запуска появилось примечание «модель не помещается в свободную видеопамять —
  будет медленнее» (плашка раз на модель за сессию); чип железа показывает
  свободную VRAM. Дубль `/api/ps` в оценке убран; `detect_vram` поднят из
  `estimate()` в `plan_inference` (1 запуск nvidia-smi на план вместо ~9);
  мёртвая команда `estimate_memory` удалена.
- **Повреждённая `documents.db` не приговор**: файл уходит в резервную копию
  `.corrupt.bak` (с уборкой WAL/SHM-сайдкаров), база пересоздаётся, приложение
  работает дальше; диагностика предупреждает о пересоздании. Классификация
  строго по кодам SQLITE_CORRUPT/NOTADB — busy/права доступа не трогаются.
  +2 юнит-теста (восстановление и «не-повреждение не сносит базу»).
- **«Стоп» действует посреди запросов**: помощник `with_cancel` (pin + timeout,
  опрос флага каждые 200 мс) оборачивает «решающие» ходы агентного режима и
  первичное подключение чата (холодная загрузка модели). Вызов веб-инструмента
  сознательно не оборачивается: журнал 152-ФЗ пишется после вызова, обрыв
  оставил бы уход в сеть без записи (сам вызов ограничен таймаутами клиента).

### Changed — Установка моделей: единый менеджер с честной отменой
Итерация 4 аудита. Раньше отменённая установка отчитывалась как «установлено»,
а параллельные закачки делили один флаг отмены.
- **Rust**: `PullState` вместо общего флага — у активной установки СВОЁ имя и
  флаг отмены; вторая параллельная честно отклоняется; гонка «второй pull
  сбрасывает отмену первого» устранена. `pull_model` возвращает итог
  `done | cancelled` (раньше успех и отмена были неотличимы); чанки ждём
  окнами по 400 мс — отмена срабатывает даже при молчащей сети, молчание
  дольше 120 с — честная ошибка («докачка продолжится с места»).
- **Фронтенд**: единый `runPull` для всех трёх поверхностей установки
  (карточка bge-m3, каталог моделей, предложение vision-модели в чате) вместо
  трёх дублей; «установлено»/«актуальна» — только при честном done; один гейт
  `pullingTag` блокирует все кнопки установки на время закачки; у vision-плашки
  появилась кнопка «Отмена». Гонка индикатора прогресса устранена счётчиком
  операций `opGen` (как `myGen` в чате) — запоздавшие сообщения канала больше
  не затирают итоговую надпись и не «подвешивают» панель. `humanError`
  применён к сырым ошибкам установки/списков моделей/документов.

### Changed — Модульность фронтенда: main.ts разрезан на модули
Итерация 5 аудита. Монолит в 3324 строки → 16 модулей + точка сборки main.ts
(74 строки): types / state / dom / util / ui / pull и модули фич (chat,
conversations, projects, documents, models, attachments, settings, online).
- Общее изменяемое состояние — один объект `state` (state.ts); все DOM-рефы —
  реестр dom.ts (live-binding `export let` + `initDom()`), id сверены с
  index.html 1:1; обработчики событий — в `wireX()` своих модулей.
- Циклы зависимостей разорваны по слоям (stop/showChatView в ui.ts; списки
  чатов проекта — в conversations.ts; `applyModelsDir` больше не обновляет
  чужие экраны сам). Циклических импортов нет; порядок инициализации
  сохранён дословно.

### Performance — Лёгкий старт: рендер ответов — ленивым чанком
Тяжёлый рендер (markdown-it + KaTeX + highlight.js + их CSS) вынесен в
отдельный чанк, который грузится В ФОНЕ сразу после старта: загрузочный JS
уменьшился с 858.7 кБ до 65.1 кБ (gzip 274.8 → 20.3 кБ). Если ответ пришёл
раньше чанка — текст показывается простым и «дорисовывается» по готовности.
highlight.js переведён с `lib/common` (~40 языков) на ядро + явные 17 языков
(python, js/ts, bash, sql, json, yaml, xml/html, css, java, c/c++, c#, rust,
go, php, 1С).

### Added — Проекты: чаты и документы, организованные как в Claude
У каждого проекта — свои чаты и своя база знаний (документы). Быстрые чаты и общие
документы по-прежнему живут вне проектов. Всё офлайн, данные не покидают ПК.
- **Модель данных**: проекты в `appDataDir/projects.json` (команды `list_projects`
  / `save_project` upsert / `delete_project` каскадом); у диалога — `project_id`
  (старые файлы читаются как «вне проектов»); у документов — столбец `project_id`
  (NULL = вне проектов), составной `UNIQUE(project_id, sha256)` (один файл можно
  держать в разных проектах). Аддитивная миграция старой схемы БЕЗ потери данных
  (при сбое — сброс индекса-кэша). Поиск, список, счётчик и дедуп документов —
  по проекту. Тесты: изоляция проектов и миграция (12 passed).
- **RAG по проекту**: чат внутри проекта ищет только по документам своего проекта;
  инструкции проекта добавляются системным сообщением ко всем его чатам.
- **UI**: в боковой панели — секция «Проекты» и список «Чаты» (быстрые, вне
  проектов); полноэкранный экран проекта (имя, инструкции, «Знания проекта» с
  добавлением документов, «Чаты проекта» с созданием чата); индикатор проекта
  открытого чата в шапке. Документы стали контекстными (проект / вне проектов),
  логика добавления/списка/прогресса переиспользуется. Модальный ввод строки
  (`promptModal`), человеческие тексты ошибок (`humanError`), чинёный таймер
  прогресса индексации.

### Added — Обновления приложения: онлайн-проверка по кнопке и установка с диска
Обновление самого приложения двумя путями, в духе офлайн-ядра: автоматических
проверок нет, единственное сетевое обращение — по явному нажатию пользователя.
- **Онлайн-путь (Tauri updater)**: плагины `tauri-plugin-updater` +
  `tauri-plugin-process`; эндпоинт — `latest.json` из GitHub Releases репозитория;
  подпись обновлений обязательна (публичный ключ зашит в `tauri.conf.json`,
  приватный — вне репозитория, в секретах CI). В `bundle` включён
  `createUpdaterArtifacts` — CI прикладывает к релизу подписанные артефакты
  и сводный `latest.json`.
- **Офлайн-путь (с диска)**: Rust-команда `install_update_from_disk` — пользователь
  выбирает файл установщика новой версии (флешка и т.п.), приложение запускает его
  штатно для ОС (`msiexec`/`.exe` на Windows, `xdg-open` для `.deb`/`.rpm` на Linux,
  `open` для `.dmg` на macOS) и закрывается, чтобы установщик заменил файлы.
  Для AppImage — честная подсказка заменить файл вручную. Без сети.
- UI: карточка «Обновления приложения» в настройках — текущая версия, кнопка
  «Проверить обновления» (строка «Доступна версия X» с заметками к выпуску и
  кнопкой установки, прогресс загрузки, перезапуск), кнопка «Установить
  обновление с диска…».

### Added — Диагностика: раздел «Проверка системы» в настройках
Самопроверка приложения для установки под ключ и поддержки: одна кнопка — и видно,
что не так. Всё локально, без интернета.
- Rust: команда `run_diagnostics` — 6 проверок с честным статусом ok/warn/fail:
  **движок** (жив + версия против минимума `MIN_OLLAMA_VERSION` = 0.17.1),
  **модели** (обязательные из `MODEL_SET` установлены), **база документов**
  (открывается; документов/фрагментов/размер), **место на диске** (том с
  `appDataDir`: < 15 ГБ — внимание, < 3 ГБ — проблема; модель 8–9B ~5–6 ГБ),
  **железо** (тот же детект, что у «светофора»: green/yellow/red → ok/warn/fail),
  **хранилище** (каталог данных доступен на запись — пробный файл).
  Команда не падает — каждая проверка отчитывается сама. Переиспользованы
  существующие `ollama_version`/`model_states`/`detect_hardware`/`docstore`;
  новых зависимостей нет (диски — через уже подключённый `sysinfo`).
  Юнит-тест разбора версии (`parse_version`, хвосты вроде `-rc1` не роняют).
- UI: карточка «Проверка системы» в настройках — список проверок с иконками и
  бейджами (ОК / Внимание / Проблема, в стиле бейджей моделей), деталью по
  каждой; запускается при открытии настроек и по кнопке «Проверить» (со
  спиннером). Строки переиспользуют вёрстку списка моделей.

### Added — Агентный режим / онлайн-слой: веб-поиск (опционально, выключен по умолчанию)
Первая надстройка над офлайн-ядром: модель может искать в интернете через
tool-calling. Офлайн-ядро не тронуто — без явного включения приложение в сеть
с данными пользователя не ходит (152-ФЗ).
- **Изоляция сети** (`src-tauri/src/tools.rs`): ОТДЕЛЬНЫЙ исходящий HTTPS-клиент
  (`web_client()`: rustls, `https_only`, таймауты 8с/20с, честный User-Agent) —
  не смешан с localhost-клиентом Ollama. Единственное место выхода в интернет
  с данными пользователя. Расширяемость: новый инструмент = +1 запись в
  `tool_specs()` и +1 ветка в `execute_tool()`.
- **Агентный цикл** (`agentic_chat` в `lib.rs`): «решающие» ходы к Ollama без
  стриминга с массивом `tools`; модель возвращает `tool_calls` (корректный
  tool-calling, не разбор текста); инструменты исполняются в Rust, результаты —
  сообщениями роли `tool`; финальный ответ — обычным стримом. Пределы:
  ≤4 раундов, ≤2 поисков на запрос; после исчерпания — ход без `tools`.
- **Веб-поиск (Tavily по умолчанию)**: до 20 источников за поиск (глубина
  `advanced`), сниппеты режутся до 200 символов — весь результат умещается в
  `num_ctx`; провайдер/эндпоинт/API-ключ настраиваются (`web_search_*` в
  `settings.json`, ключ хранится только локально, в гит не попадает).
- **Прозрачность (152-ФЗ)**: журнал исходящих обращений (инструмент, запрос,
  URL, время) — команды `get_outbound_log`/`clear_outbound_log`, просмотр в
  настройках; в шапке индикатор «Онлайн · данные могут уходить наружу»;
  веб-источники показываются под ответом (как источники RAG).
- **UI**: тумблер «Онлайн» в строке ввода + главный выключатель в настройках
  (раздел «Онлайн-режим и инструменты»: провайдер, эндпоинт, ключ, журнал);

  возможностям: модель без `tools` → уведомление и обычный офлайн-чат.

### Added — Стабильность: защита от зависания при инференсе (своп)
Машина больше не уходит в неотзывчивость на запросе: движок настроен экономно, память
оценивается по формуле ДО запуска, при нехватке подбирается модель полегче, а в процессе
watchdog следит за свопом и аккуратно прерывает опасный запрос с точной причиной.
- **Экономный режим движка** (`engine.rs`, когда движок наш): `OLLAMA_MAX_LOADED_MODELS=1`
  (главный фикс — чат + bge-m3 + зрение не висят в памяти разом), `NUM_PARALLEL=1`,
  `FLASH_ATTENTION=1`, `KV_CACHE_TYPE=q8_0`, `KEEP_ALIVE=5m`. Внешнему движку не навязывается.
- **Оценка памяти по формуле** (`estimate_memory`): вес (`size` из `/api/tags`) + KV-кэш
  (метаданные `/api/show` × контекст, q8_0, учёт GQA) + compute-буфер + запас, против
  доступной памяти. Учитывает `/api/ps` (уже загружено / выгрузится при `MAX_LOADED_MODELS=1`)
  и унифицированную память Apple (на macOS «available» недосчитывает кэш → пол ~55% total).
  Результат: ok / впритык / не помещается + лимитирующий ресурс.
- **Лестница смягчения** (`plan_inference`): снизить контекст (8192→4096→2048, параметр
  `num_ctx` у `chat_stream`) → подобрать более лёгкую модель той же роли «вниз» → честный
  отказ с дефицитом. Только «вниз»; ручной выбор приоритетен, downscale — лишь на запрос.
- **Watchdog** (в `chat_stream`): лёгкая задача (раз в 1.5 с) следит за РОСТОМ свопа; при
  >512 МБ взводит существующий `CancelFlag` (без нового механизма отмены) и возвращает
  точную причину (оперативная память). `CancelFlag` переведён на `Arc<AtomicBool>`.
- **UI**: спокойные плашки — пост-фактум при подборе модели/контекста, честный отказ до
  запуска, понятная причина прерывания. Пороги/буферы/тексты — в константах (точки настройки).

### Added — Зрение и OCR (vision-модели)
Приложение понимает изображения: прикрепить картинку → спросить по ней или распознать
текст (OCR) — всё офлайн через vision-модель (`qwen2.5vl`, `qwen3-vl`).
- Rust: `ChatMessage.images: Vec<String>` (сырой base64, `skip_serializing_if` — в
  текстовых сообщениях не появляется); команда `read_image_base64` (без префикса
  `data:`, проверка типа/размера ≤12 МБ); `list_models` отдаёт capability `vision`.
  Зависимость `base64` (MIT/Apache). `chat_stream` не изменён — картинки едут в `messages`.
- Фронт: кнопка «Прикрепить изображение» + превью с «убрать»; base64 кладётся в
  `images` сообщения через `buildApiMessages`; изображение сохраняется в истории и
  рисуется в пузыре. Гейт vision-модели: текущая умеет → используется; не умеет, но
  есть другая → авто-переключение с уведомлением; нет вовсе → предложение установить.
- OCR: действие «Извлечь текст» — тот же vision-запрос с OCR-промптом на русском.
- Зрение **отделено от RAG** (картинки не эмбеддятся/не индексируются); сеть только из Rust.

### Added — Управление моделями: состояние, источник, проверка обновлений
Зрелое управление вместо бинарного «есть/нет»: видно состояние каждой нужной модели,
обновление по digest, выбор источника (онлайн или с диска).
- Rust: расширяемый список `MODEL_SET` (роль/тег/обязательность); команда
  `model_states` — локальное состояние (установлена + digest/размер/дата) без сети;
  `check_model_updates` — сравнение **sha256 манифеста из реестра** Ollama с локальным
  digest → актуальна / есть обновление / не установлена (онлайн, по запросу). Добавлен
  `rustls-tls` (чистый Rust, MIT/Apache) — единственный выход в интернет, по кнопке.
- Источники: **онлайн** (`pull_model` по тегу = установка ИЛИ обновление) и **с диска**
  (офлайн-поставка `set_models_dir`/`reload_engine`) — переиспользованы, не дублированы.
- UI: на странице настроек раздел «Модели» — список с состоянием (цветные бейджи),
  иконки ролей, действия по состоянию (Установить/Обновить), кнопка «Проверить
  обновления» с итогом прямо в кнопке (Актуально/зелёный, Есть обновления/жёлтый),
  вращением стрелок при проверке и сохранением итога на сессию. Прогресс/отмена при
  установке/обновлении; края (нет сети, внешний движок). Отступы между блоками настроек.

### Added — Документы: прикрепление файла (Фаза A) · `8ccb4f2`
- Команда Rust `extract_document(path) → { name, ext, text, chars }` — извлечение
  текста из **PDF / DOCX / TXT / MD** чистым Rust, без сети и без Python/C-движков
  (`pdf-extract`, `quick-xml`, `zip` c фичей `deflate`). Скан-PDF без текстового
  слоя → понятная ошибка (OCR — отдельный этап).
- Плагин `tauri-plugin-dialog` для нативного выбора файла; разрешение `dialog:default`.
- Прикреплённый файл визуализируется карточкой в пузыре сообщения (бейдж формата
  PDF/DOCX/TXT/MD + имя + размер); при отправке поле ввода очищается, файл

### Added — Документы: база и семантический поиск (RAG, Фаза B) · `d487f15`
Документы превращаются в постоянную базу с поиском по смыслу; в модель уходят не
целые файлы, а найденные релевантные фрагменты. Всё офлайн.
- **B1 — Векторное хранилище** (`src-tauri/src/docstore.rs`): `rusqlite` (feature
  `bundled`) + `sqlite-vec`; БД `appDataDir/documents.db`; виртуальная таблица
  `vec0` с **косинусной** метрикой; таблицы `documents`/`chunks`/`meta`; версия
  схемы (`PRAGMA user_version`) с безопасным пересозданием; защита от смены
  размерности вектора. Юнит-тесты на регистрацию расширения и KNN.
- **B2 — Эмбеддинги** (`src-tauri/src/embed.rs`): `bge-m3` через Ollama `/api/embed`
  **батчем**; размерность определяется из ответа (1024), не хардкодится; понятное
  сообщение при отсутствии модели (HTTP 404). `keep_alive=30s` — модель не висит
  в памяти зря (см. «Оптимизация памяти»).
- **B3 — Чанкинг и индексация** (`src-tauri/src/chunk.rs`): резка по естественным
  границам (абзацы → предложения, перекрытие ~12 %, числа в константах);
  идемпотентность по **sha256** содержимого; прогресс индексации через `Channel`.
- **B4 — Поиск**: команда `search_documents(query, k) → RetrievedChunk[]` —
  эмбеддинг вопроса → KNN top-k с метаданными источника (документ, № фрагмента).
- **B5 — Встраивание в чат + интерфейс базы**: фрагменты вставляются как
  `CONTEXT` **перед** вопросом в существующий `chat_stream` (поток не изменён);
  бюджет `num_ctx` соблюдается (история урезается при активном поиске); под
  ответом — источники. Интерфейс — **вкладки сайдбара «Диалоги | Документы»**
  (список, добавление, удаление, прогресс), отдельно от истории диалогов.
- **B6 — Честная обработка краёв**: пустая база → обычный чат; нет `bge-m3` →
  подсказка/установка; вопрос не по документам → обычный ответ; битый файл →
  понятная ошибка; смена модели эмбеддингов → пересоздание базы с предупреждением.

### Added — Операционный слой: управление процессом Ollama
Приложение само обеспечивает работу движка — пользователю не нужен терминал.
- Модуль Rust `engine.rs` + команда `ensure_engine`: при старте **переиспользует**
  запущенную Ollama либо **поднимает свою** (`ollama serve` с `OLLAMA_HOST=127.0.0.1:11434`),
  дожидаясь готовности (опрос `/api/version`, до ~30 с на холодный старт).
- **Останавливает только тот процесс, что запустило само** (`started_by_us`), на
  выходе (`RunEvent::Exit` → `stop_if_ours`); внешний/системный экземпляр не трогает.
  Гашение со всеми дочерними: Unix — группа процессов (`process_group` + `SIGTERM`,
  ожидание ~3 с, затем `SIGKILL`); Windows — `taskkill /T /F`.
- **Гибкое разрешение путей** к движку без захардкоженного абсолютного пути: override
  из настроек (`ollama_path`/`ollama_models_dir`) → ресурс рядом с приложением → PATH
  и типичные места (последние — как fallback под `#[cfg(target_os)]`). Задел под
  будущую офлайн-поставку (инсталлер заполнит override).
- Каталог моделей: при отсутствии override **явно убираем унаследованную** из
  окружения `OLLAMA_MODELS` — чтобы движок использовал свой каталог по умолчанию,
  как системный (иначе поднятый движок не видел моделей).
- UI: статус «Запуск движка…»; края `not_installed`/`error` — честно.
- Проверено вживую на macOS: переиспользование, запуск своего движка, гашение
  только своего процесса (без осиротевших), грациозная остановка.
- Зависимости: `tokio` (feature `time`), `libc` под `cfg(unix)` — MIT/Apache.

### Added — Офлайн-поставка движка и моделей с диска
Замыкает офлайн-контур: у air-gapped клиента приложение находит движок и модели на
диске и работает без интернета. Опирается на гибкое разрешение путей из `engine.rs`.
- Команды Rust: `set_engine_path` / `set_models_dir` (с валидацией — исполняемый
  файл по биту исполнения/`.exe`; каталог моделей по наличию `manifests`+`blobs`),
  `clear_engine_overrides`, `reload_engine` (перезапуск **нашего** движка с новым
  `OLLAMA_MODELS`; внешний/системный не трогаем — честно «применится при запуске»).
  Пишут в те же ключи, что читает `engine.rs`. Юнит-тесты валидаторов.
- Офлайн-установка моделей: указать предзагруженный каталог Ollama → запись override
  → движок поднимается с ним; список моделей и статус эмбеддера обновляются. Без сети.
- Онлайн-провижининг (`pull_model`) не тронут — офлайн добавлен как альтернатива.
